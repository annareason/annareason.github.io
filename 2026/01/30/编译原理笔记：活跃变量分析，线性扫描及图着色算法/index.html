一、活跃变量分析

活跃变量分析是一种逆向分析，它的核心目标是确定在程序的任意一点，哪些变量的值在后续的执行中还会被用到（即“活跃”的）。

1. 基础定义

  • def[n]：在节点 n 中被定义（赋值）的变量集合。简单来说，就是指令左侧的变量。
  • use[n]：在节点 n 中被使用（读取）的变量集合。简单来说，就是指令右侧的变量。
  • in[n]：到达节点 n 时，处于活跃状态的变量集合。
  • out[n]：离开节点 n 后，仍处于活跃状态的变量集合。

2. 核心公式

数据流分析的核心是通过迭代计算，让 in 和 out 集合收敛到稳定值：

  • 计算顺序：必须从程序的出口（如 return 语句）开始，从下往上逆向计算。
  • 初始状态：将所有 in[n] 和 out[n] 初始化为空集 ∅，然后迭代更新，直到集合不再变化。

3. 实战示例

我们来看一段简单的循环代码：

对它进行活跃变量分析的关键步骤：

  1. 首先，为每个指令行确定 def 和 use 集合。

    语句 def[n] use[n]
    a ← 0 {a} ∅
    L1: b ← a + 1 {b} {a}
    c ← c + b {c} {c, b}
    a ← b × 2 {a} {b}
    if a < N goto L1 ∅ {a}
    return c ∅ {c}

  2. 先假设in 和 out初始填充均为∅，然后从最后一行 return c 开始，逆向更新 in 和 out。

  3. 由于存在循环，需要多次迭代，直到所有 in 和 out 集合都不再变化。

    • 第一次迭代：
    语句 in[n] out[n]
    a ← 0 {c} {a, c}
    b ← a + 1 {a, c} {b, c}
    c ← c + b {b, c} {b, c}
    a ← b × 2 {b, c} {a, c}
    if a < N goto L1 {a, c} {c}
    return c {c} ∅
    • 第二次迭代：
    语句 in[n] out[n]
    a ← 0 {c} {a, c}
    b ← a + 1 {a, c} {b, c}
    c ← c + b {b, c} {b, c}
    a ← b × 2 {b, c} {a, c}
    if a < N goto L1 {a, c} {a, c}
    return c {c} ∅

    第二次迭代后发现in[n]与out[n]不再发生变化了，故第二次迭代结果即最终的活跃变量分析。

二、线性扫描算法：寄存器分配的高效实现

有了活跃变量分析的结果，我们就可以进行寄存器分配了。线性扫描是一种简单高效的寄存器分配算法，它直接利用活跃变量的生命周期来分配寄存器。

1. 核心思想

  1. 确定生命周期：根据 in[n] 和 out[n]，确定每个变量的“起始活跃点”（首次出现 in 的位置）和“结束活跃点”（最后出现 out 的位置）。
  2. 扫描分配：按程序执行顺序（从上到下）扫描，为每个活跃的变量分配一个空闲寄存器。
  3. 溢出处理：如果没有空闲寄存器，就选择一个“结束活跃点最晚”的变量，将其溢出到内存，腾出寄存器给当前变量。

2. 实战示例

假设我们只有2个寄存器 R1、R2，并分析这段代码：

  1. 我们先为每个变量确定其活跃区间。

    语句 $\text{in}[n]$ $\text{out}[n]$
    $a=!$ $\phi$ ${a}$
    $b=!$ $\phi$ ${b}$
    $(a>b)?$ ${a,b}$ ${a,b}$
    $x=a-1$ ${a}$ ${x}$
    $\text{goto L}_1$ ${x}$ ${x}$
    $x=a+b$ ${a,b}$ ${x}$
    $!=x$ ${x}$ $\phi$
    $\text{ret}$ $\phi$ $\phi$

    列出单个变量的活跃区间（//表示某变量开始活跃和结束活跃的语句，开始结束之间就是活跃变量区间，用\\表示）。

    行 a b x

    2 \\\ \\\ —
    3 \\\ \\\ //
    4 \\\ \\\ \\\
    5 // — //
    6 — — —

    • 一开始，a 和 b 分别占用 R1 和 R2。
    • 当处理到 x 时，寄存器已满。由于 x 是最后活跃的变量，我们选择溢出它。

三、图着色算法：寄存器分配的经典理论

图着色是寄存器分配的经典理论模型，它将问题转化为一个图的着色问题，要求相邻节点（即活跃区间有重叠的变量）不能使用相同的颜色（即寄存器）。

1. 核心思想

  1. 构建冲突图：每个变量是一个节点，如果两个变量的活跃区间有重叠，则在它们之间连一条边。
  2. k-着色尝试：我们的目标是用 k 种颜色（k 为寄存器数量）为图着色，使得相邻节点颜色不同。
  3. 删除与回填：不断删除度数小于 k 的节点，直到剩下一个子图。如果子图为空，说明可以着色；否则，需要溢出一些节点。
  4. 溢出处理：对于无法着色的节点（spilled），将其溢出到内存，然后重新尝试着色。
